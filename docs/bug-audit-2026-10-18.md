What this change does: World loading keeps geometry and collision when a texture
dictionary is absent. Opaque and translucent triangles no longer share one draw
batch, so a glass pane cannot disable a solid floor's fallback collision or depth
writes.

This is a skill-guided [Ponytail Review](https://github.com/DietrichGebert/ponytail/blob/main/skills/ponytail-review/SKILL.md),
performed before pushing the change, against `main` at `3461ed6b`. It is not a
separate external review service. The assumed load is one native client streaming
the existing bounded regions, including its existing 20-player session limit.

## Must fix — resolved

1. **A missing TXD hides the entire placement** (`native/crates/scene/src/lib.rs`, `WorldLoader::load_area`)
   - **What this is:** The loader selects models from the installation archive before loading their textures.
   - **Problem:** Requiring both DFF and TXD entries discards untextured models and prevents the existing texture fallback and inheritance paths from running. Collision belonging to that placement is discarded too.
   - **Fix:** Require the model entry here and leave texture resolution to the existing resolver. A generated IMG containing the repository's own room DFF now loads with no TXD, with both visual fallback collision and an explicit COL tested.
   - **If we skip it:** A missing or unnecessary dictionary can remove scenery and solid ground; a region containing only that placement fails to load.

2. **Glass disables solid geometry using the same texture** (`native/crates/scene/src/lib.rs`, `add_model`)
   - **What this is:** A draw batch groups triangles that use the same texture and animation state.
   - **Problem:** One translucent triangle marked the entire batch as translucent. The renderer then stopped writing depth for its opaque triangles, and fallback collision discarded the whole batch. The regression produced no floor beneath an opaque triangle when a translucent triangle shared its texture.
   - **Fix:** Keep opacity in the batch identity, including opacity stored in vertex colors. All connected texture lookups strip the draw-state suffix while retaining the full batch key for GPU uploads, animation and vehicle parts.
   - **If we skip it:** A floor can become non-solid and opaque scenery can draw in the wrong order because an unrelated transparent surface shares its texture.

## Connected-code review

Reviewed the diff, README, world candidate selection, texture inheritance,
original and mod resource loading, fallback collision, vehicle paint/reflection
masks, ped and clothing animation, weapon and cutscene loading, GPU uploads,
texture reuse and opaque/blended render pipelines. The new suffix is handled by
each caller of the shared model builder. Texture names are not split on arbitrary
pipe characters. Triangle counts and geometry budgets remain unchanged; a mixed
batch can now require separate opaque and translucent draws and texture copies.
There are no new dependencies or per-frame world-loading jobs.

No remaining must-fix findings were found in this change. This was a focused audit
of world loading, material batching and connected collision/render paths, not an
exhaustive review of the server or the entire project.
