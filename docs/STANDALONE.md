# Standalone SARE: running without San Andreas

Goal: SARE should be a platform in its own right. A server owner should be
able to ship a game mode with its own world, characters, vehicles and sounds,
and a player should be able to join it **without owning or installing GTA San
Andreas**. The original game then becomes one optional *content pack* among
others, still read only from the player's own installation, exactly as today.

This document records how the code depends on San Andreas data now, the plan
to remove that dependency step by step, and what the first step delivers.

Hard rules, unchanged from [AGENTS.md](../AGENTS.md): never commit Rockstar
files or anything converted from them, and never use the game executable or
decompiled code. Standalone content must be original, generated by code, or
under a licence that allows redistribution (CC0 / CC-BY), with its source and
licence recorded next to it.

## Current dependency inventory

What `sa-runtime` and the launcher read from the installation today:

| Area | Original files | Code | Standalone replacement |
| --- | --- | --- | --- |
| Installation check | `models/gta3.img`, `data/default.dat`, `data/gta.dat`, `anim/ped.ifp`, the IDE/IPL files they list | `sa-client::install::validate`, launcher | Content-pack validation per pack; the SA check only for the SA pack |
| World geometry and collision | `gta3.img`/`gta_int.img` DFF, TXD and COL; IDE definitions; text and binary IPL placements | `sa-scene::WorldLoader`, `sa-assets` (RenderWare DFF/TXD/COL readers) | `WorldSource` implementations: SARE Testbed (done), then glTF scenes with collision meshes |
| Streaming world layout | IPL placements around the player, LOD links, interiors and ENEX portals | `WorldLoader::load`, `load_interior` | Pack-defined cells/tiles; portals as data in the pack |
| Player character and animation | Ped DFF/TXD in `gta3.img`, `anim/ped.ifp`, `data/peds.ide`, clothing | `sa-scene::ped`, `sa-assets::ifp`/`skin` | An original rigged character (glTF skin) with original animation clips |
| Vehicles | Car DFF/TXD, `data/vehicles.ide`, `data/carcols.dat`, `data/handling.cfg` | `sa-scene::vehicle`, `vehicle_list`, `handling` | glTF vehicle with named wheel/door nodes and a handling table in the pack; `Handling::default()` already exists |
| Weapons | `data/weapon.dat`, weapon models | `weapon_list`, `weapons.rs` | Pack weapon table and models |
| Traffic and pedestrians | `data/paths/nodes*.dat`, ped/car groups | `sa-scene::roads`, `traffic.rs`, `crowd.rs` | Pack-defined road graph (JSON), or no traffic |
| Water | `data/water.dat` | `sa-scene::water` | Pack water planes, or none |
| Time of day and weather | `data/timecyc.dat` | `runtime::daycycle` | Built-in default colour curve |
| Zone names and text | `data/info.zon`, `text/american.gxt` | `runtime::zones` | Pack zone list; UI text is already SARE's own |
| Radar and map | `radar00.txd`–`radar143.txd` | `sa_scene::load_radar_tiles`, `menu/map.rs` | Pack map image, or a generated top-down map |
| Audio | SFX archives (`audio/CONFIG/*.dat`, `audio/SFX`), streams | `sa-audio` | OGG/WAV files in the pack (kira already plays them) |
| Particles, generic textures | `models/particle.txd`, `models/generic/vehicle.txd` | runtime effects | Small original textures in the repository |
| Cutscenes and missions | `cutscene.img`, `anim/cuts.img` | `sa-script`, debug flags only | Not needed for the platform |

Already independent: the dedicated server (`sa-server`) and the relay never
read game files; server and client Lua, the resource system, routing buckets,
server entities, the script UI and the launcher's own interface use SARE's
own code and font. Native resources (`resource.json`) already add models and
placements on top of the world, but they are RenderWare files placed into the
SA world and still need the installation underneath.

## The plan

### 1. Content abstraction (first step, in this PR)

- `sa_scene::content::ContentSource` names where the world comes from:
  `Original(game_dir)` or `Testbed`, chosen with `--content original|testbed`.
- `sa_scene::content::WorldSource` is the seam the runtime streams through:
  `load(center, origin, radius) -> Scene` and an optional `spawn()` point.
  `WorldLoader` (the SA installation) implements it unchanged.
- `sa_scene::testbed` builds **SARE Testbed** in code: a 512 m checkered
  ground, a walking ramp to a platform, stairs, jump blocks and a long driving
  slope, with collision. It contains no third-party assets.
- `sa-runtime --probe-standalone` loads the testbed and walks a player up the
  ramp without looking for a San Andreas installation. It is meant to run in
  CI on every platform (`cargo run -p sa-runtime -- --probe-standalone
  --content testbed`); that workflow step still has to be added.

### 2. Boot the runtime into the testbed

Make `sa-runtime --content testbed` start a window: stream through
`WorldSource`, and give every SA-only system a "not available" state instead
of an error (radar, zones, day cycle, traffic, water, audio). The player is a
simple original capsule character and the camera works as today. The
launcher gets a "SARE Testbed (no game files)" entry next to the installation
picker. This is mostly plumbing in `runtime/src/main.rs`, where startup today
assumes `game_dir` everywhere.

### 3. Content packs

A content pack is a folder (or zip) with `content.json`:

```json
{
  "id": "sare-testbed",
  "name": "SARE Testbed",
  "version": "1.0.0",
  "license": "MIT",
  "world": { "kind": "gltf", "scene": "world/testbed.glb", "spawn": [0, -12, 10] },
  "characters": [{ "id": "runner", "model": "characters/runner.glb" }],
  "vehicles": [{ "id": "kart", "model": "vehicles/kart.glb", "handling": "vehicles/kart.json" }],
  "sounds": { "engine": "sounds/engine.ogg" }
}
```

- **Formats:** glTF 2.0 (`.glb`) for meshes, skins and animation clips; PNG
  or KTX2 textures; OGG/WAV audio; JSON for tables. These are open,
  engine-agnostic and supported by Blender, so creators do not need any
  RenderWare tooling. A `gltf` reader goes into `sa-assets` next to the DFF
  reader and produces the same `Scene` and `Batch` types.
- **Collision:** a separate low-poly glTF mesh or primitive shapes in the
  pack, fed to the existing `CollisionWorld`.
- **The SA pack:** "San Andreas (your installation)" becomes a built-in pack
  whose loaders are today's code. Nothing about it is redistributed; it is
  only enabled when the player selects their own installation.
- **Servers name packs:** a server announces the pack its world needs, e.g.
  `set sv_contentPack "sare-testbed"`. Players download free packs through the
  existing SHA-256 resource cache; the SA pack is never downloaded, only
  required, so the join screen can say "this server needs your own copy of San
  Andreas" or "no game files needed".
- **Native resources on top of a pack:** `resource.json` gains glTF models,
  so mods work the same on any world.

### 4. Original default content

Built and stored in the repository, each with its licence and source file:

- The testbed world (step 1), later a small original town block in glTF.
- One rigged character with walk, run, jump and idle clips.
- One or two simple vehicles (a kart and a box truck) with handling tables.
- A few CC0 sounds (engine loop, footsteps, UI clicks), recorded or picked
  from CC0 libraries, with attribution files.

### 5. Server-side independence

Server scripts use world coordinates and model names. Model names will be
resolved per pack (`CreateVehicle('kart', ...)` in the testbed pack,
`'infernus'` in the SA pack), so the same server API works for every pack.
Server entities already travel as names or hashes, and the client already
skips models its content does not have.

## Risks and open questions

- Many runtime systems assume SA coordinates around Grove Street (`ORIGIN`).
  The testbed currently sits at world (0, 0); a pack should be able to set its
  own origin.
- Car physics is tuned for SA cars; pack vehicles need their own handling
  values and wheel layout read from named glTF nodes.
- Animation is the largest piece: the SA ped skeleton and IFP clips must be
  replaced by an original skeleton and clips for standalone packs.
- Asset licensing must be checked for every file a pack ships; CI should
  refuse packs without a `license` field.
